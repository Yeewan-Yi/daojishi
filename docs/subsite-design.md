# 子页面设计与接入规范

目标：新页面像有期和拾光的自然延续，同时让两个人能独立开发，减少冲突。

## 视觉

优先复用 `shared/subsite.css` 的 `--paper`、`--ink`、`--muted`、`--line`、`--accent`、`--wash`。默认浅蓝灰 / 深黑蓝，页面可在自己的 CSS 中覆盖变量，但必须同时定义深浅两套。不要改共享样式只为满足自己的页面。

字体已在仓库中：汉字 `var(--font-han)`，普通数字 Times New Roman；航行主题 IBM Plex Mono；倒计时 Libre Baskerville。品牌和小图标从 `symbols.js` 复用，新增原创细线几何图标，避免直接拷贝游戏资源。

顶部品牌 → 页面名 → 站内导航和明暗图标；正文大标题下可有短引言。开放排版、细分隔线、充足留白，不要多层套卡片。图标悬停时文字在右侧慢慢展开，外轮廓不做胶囊。

普通筛选、选择、修改尽量就地展开，少遮挡页面。过渡约 250–500ms，明暗过渡约 600ms；加载快时不强制等待动画；长列表分页/按需加载，媒体缩略图优先，避免一次下载原图。`prefers-reduced-motion` 下关闭动画。

## 结构和接口

```text
pages/<slug>/index.html  本页结构
pages/<slug>/page.css    本页样式
pages/<slug>/page.js     本页业务
pages/<slug>/assets/     少量公开设计资源（不放私人影像）
shared/subsite.css      公共页面外观
shared/subsite.js       品牌、主题、站内链接
pages/registry.json     自动登记的子页面目录
```

模板使用相对路径，在 GitHub Pages 的 `/daojishi/` 子目录也能工作。不要把资源写成 `/shared/...` 或 `/vendor/...`。新资源使用本地预览服务器允许的扩展名；需要额外路径时说明原因。

## 共议：新页面自动获得建议入口

新模板调用 `initSubsite({name:'页面名'})` 时，会自动向 `.site-nav` 加入「共议」图标。不必复制建议列表、数据库代码或自己造一套评论区。入口识别 `pages/<slug>/`，归属 ID 为 `page:<slug>`。页面依旧只需要维护自己的三个文件。

`pages/registry.json` 决定主站里可选择的网站名称。生成器会登记它；PR 合并后，总站「共议」即可选择新页，且同一建议可以同时归属多个网站。未合并时请在自己 Fork 的本机预览验证，不要以为已经出现在正式站。

若页面不使用公共导航，在页面初始化完成后调用：

如果仍使用公共导航、只是路径比较特殊，可直接传 `initSubsite({name:'页面名',site:'page:our-story'})`，不必单独挂载。下例适用于自行实现导航的页面；若同时调用公共初始化，先设 `suggestions:false`，避免先生成一个默认入口。

```js
import {mountSuggestionLink} from '../../suggestions-link.js';
mountSuggestionLink({host:document.querySelector('你的导航容器'),site:'page:our-story',shared:true});
```

`shared:true` 对应共享模板样式；主站和拾光沿用自己的导航样式。自定义目录需手工登记同一个 ID 对应的 slug；正式页面仍建议保持 `pages/<slug>/index.html` 结构。需要暂时隐藏模板入口可传 `initSubsite({name:'页面名',suggestions:false})`，只适用于不发布的视觉实验。

主站入口进入总览，子网站入口默认只看本站。子网站提交的建议会自动带上本站归属；总览可选多个目标。转交改变当前目标，但原站仍能回看来源和转交流程。共议使用同一房间和双人专属身份，链接上下文会在站内保留；`?mode=local` 明确只作本机演示，不会发给对方。

Fork 是代码协作方式，不自动共享身份。如果要把子网站放在完全不同的域名或仓库，先在 PR 约定统一入口和身份衔接，不要写死私人分享链接，也不要未经确认跨域传递个人凭证。

主题存于 `youqi.theme`，与现有页面保持一致；站内返回保留分享上下文。本机草稿 key 需要页面独有前缀；不要用用户文字拼接 innerHTML，显示文字用 textContent。不要记录、转发或在截图中展示私人链接的 hash。

## 提交验收

- 桌面和窄屏可用，入口、关闭和返回可理解。
- 深浅主题可读，键盘可操作，表单有 label，异步状态有 role=status。
- 空白、加载、失败、成功状态有对应界面，操作不会跳出多余加盖弹窗。
- 本机演示与真实共享有清晰边界；权限由服务端校验。新增上传先确认存储位置和配额。
- `node scripts/check-subsites.mjs` 和 `npm test` 通过。
- PR 附完整预览路径、两种主题截图、已实现/未接入内容。

## 页内共议与输入标记

共议在当前页面右侧展开，不再单开子页面。`initSubsite()` / `mountSuggestionLink()` 的接入方式保持兼容，新页面自动获得侧栏。关闭后保留建议和回复草稿；原共议网址会回到对应页面并展开侧栏。

输入开头的 `【拾光】建议正文` 会自动识别归属；`【有期】【拾光】建议正文` 指定多个网站。名称取自注册目录，也可用 `【page:our-story】` 或 `【our-story】`，总站别名为 `【总站】`。只有开头的标记会被解析，正文中的括号保持原样。未知或重名标记会提示更正，避免误投。子网站的原始归属始终保留，其他标记可增加目标。

本机预览：`index.html?mode=local&council=1`。模板开发仍用本机演示，不需额外数据库或凭证。

手机顶部工具由公共模块自动收拢：保留常用入口与「更多」按钮，其余以图标加名称原位展开。复用原按钮保留事件和权限，宽屏恢复原顺序；新子页面无需重复实现。
