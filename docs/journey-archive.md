# 拾光：实现与上线说明

2026-10-23 本地照片助手：`local-assistant/` 提供可离线运行的 CLIP Q8 模型分析、清晰度/相似度排序和本机审阅网页。模型权重位于 Windows LocalAppData，图片、embedding、分析结果均不进入公开构建；GitHub Pages 仅展示通过个人能力校验的共享封面。已禁用全局 fetch 后对 87 张授权照片完成推理，输出五张候选及待核对名称，不声称已启用 GPU 或训练个人偏好模型。排序器训练脚本需要人工保存的偏好示例，先留出验证再供分析器采纳。网页 84 项检查、私有数据库 27 项检查及本地模型排序 3 项检查通过。

2026-10-22。已通过官方 Supabase CLI 浏览器登录恢复管理访问，部署新增 SQL 与 `youqi-journey-media` 函数，并通过真实私有存储联调。R2 尚未配置，当前使用有容量保护的 Supabase 私有存储。

上线验证：82 项网页 / 地图检查、20 项独立 PostgreSQL 检查，以及 18 项真实云端检查通过。真实检查使用两个独立临时房间，验证城市状态同步、照片和视频直传、签名分段读取、双人评论、重复请求与跨房间拒绝；测试对象及房间已清理。现有倒计时、传书和私人影像未用于测试。上线前后 advisors 的 8 条 warning 相同，均为原有 public 函数，未出现新增 journey 对象警告。

导航新增「版本手记」，以日期和版本记录最近有效变化，主站与拾光共用 `release-notes.js`；后续发布时同步更新此列表，不记录未部署的计划。

2026-10-23 更新：拾光改为按城市与月份使用的紧凑相册，桌面 4–6 列、手机 3 列，可切换舒展网格。列表继续以 20 份为一页从服务器读取，随滚动追加；月份和照片 / 视频筛选均由服务端执行，不局限于已加载的一页。月份统计只返回小型计数，不读取影像二进制。大图支持前后翻看与方向键；初始和换月请求超过 350 ms 后出现飞机加载反馈。

批量导入支持文件夹或多选，每批最多 200 份，仅为前 12 份生成选择预览，逐份转换与上传，避免同时解码整批照片。失败后保留未完成的队列，当前页面可重试。此队列不是跨刷新持久化任务；上传期间刷新会提示。每日每人保护上限调整为 1000 份，容量保护不变。统一归档日期可选；未指定时按文件修改日期归档，不声称读取 EXIF 拍摄时间。仍保存轻量查看副本，并非原件备份。R2 尚未配置，实际大量长期照片仍须在现有容量保护线前接入独立对象存储。

地图近景在清晰数据就绪后整体过渡到矢量地表，中国地表与省界使用同一套数据；停用近景的重复海岸和模糊纹理叠层。地表三角形只细分超长边，并使用球面法线，避免细分不一致产生透海裂缝和三角明暗面。选中城市时继续开放地图点选，点击其他地区会清除旧城市详情，无需先关闭地图。

验证：84 项网页 / 地图测试、25 项独立数据库检查、21 项真实云端检查通过。浏览器用 120 张合成照片验证月份与连续分页，并实测一批 24 张本机导入；真实云端测试仍仅使用可清理的独立房间。细节、颜色和文案微调不单独写入面向用户的版本记录。

## 页面与地图

- `memories.html` 为淡蓝色的「拾光」，沿用方正宋刻本秀楷和主站排版。按城市组织照片、视频、日期、文字与单份资料评论。桌面为开放式双列影像，手机自适应；图片和视频查看窗口有过渡。
- 主站「履痕」可选择国家、省州、城市，再手动点亮城市行政区域。中国内地城市采用本地 DataV 城市边界；台湾地区使用中国入口下的台湾省，海外城市及台湾省内城市通过共享后的城市搜索获取区域。港澳作为中国地区入口。已有南京、绍兴保留。
- 取消点亮不删除影像或评论；有资料的城市仍保留在拾光的目录中。
- 全球详细海岸线及省州分区按国家加载，使用 Natural Earth 10m；中国省级分区采用 DataV。小国的近景使用实际矢量面；邻近海岸和陆地同样使用详细矢量，并在外围柔和衔接原地表，避免只修复国界而背景依然模糊。深度放大同时平滑收窄视角，便于查看面积很小的国家。
- 国家 / 城市选中后，继续反向滚动可以放大，或使用面板的加减按钮。退出深度放大后，同一方向滚动继续回到原页面，继而进入倒计时。近景自动收起遮挡地图的航线；城市仍可旋转，深度放大时降低拖动灵敏度。
- 「履痕」为足迹与行路意象，「有期」为沙漏与航线的原创线描标记。「拾光」入口使用画页与风景意象，以文字、留白和线条衔接两页。

## 身份与隐私

沿用现有 `room/key/person/note` 专属链接，不新建公开账号，不将密钥放入 URL query。跨页仍使用 fragment；页面与存储请求不发送页面引用地址。手动编辑、照片视频和评论需要现有的个人身份。普通房间查看链接仅能看城市地图，不能读取影像或评论。

新私有表均启用 RLS，无匿名/普通登录用户的直接读写权限。公开入口为 security invoker 包装；实际能力校验在未暴露 schema 中，核对房间和个人哈希凭证。内部上传、签名和地理搜索仅服务端角色可执行。前端不包含服务端密钥。

本机预览可使用 `?mode=local`，明确显示「仅此设备」，资料保存到此浏览器的 IndexedDB；这不是云端同步或备份。云端连接失败不会偷偷转为本机保存。模式之间不自动迁移资料。

## 影像存储

- 影像文件独立存放；数据库仅保存城市、文件索引、作者、标题、日期、说明与评论，禁止 Base64 文件入库。
- 当前接入支持私有 Supabase Storage；配置 R2 服务端环境后，新上传自动转到私有 R2。历史记录保存 provider 和对象键，因此新旧资料可以共存，不强制一次迁移。
- 浏览器先申请上传位置，然后直接向对象存储上传，二进制文件不经过 Supabase Edge Function 中转。服务端核对真实大小、MIME 和文件头后，才将资料发布到回忆列表。
- 照片生成 1600 像素以内、1.2 MB 以内的 JPEG 查看副本，以及 480 像素以内的 JPEG 缩略图；不是原图备份。原件仍由私人硬盘/相册另行保存。
- 视频支持 MP4 / WebM，每段 40 MB、10 分钟以内，保存一份视频和 JPEG 封面。当前不自动转码，不保存额外视频副本，不支持长片段/HEIC 原件。若未来开放更大视频，先完善可恢复分片上传、转码、任务队列和对应容量保护，再提升上限。
- 每页 20 份资料；列表只读缩略图，点开才获取清晰图 / 视频。临时查看地址 15 分钟，前端缓存 12 分钟；视频不自动播放。
- Supabase 存储在约 700 MB 时拒绝新预约，统计现有其他存储及新资料预约，保留容量余地；R2 初始保护线为 7 GB。这是本项目设置的保护线，不是供应商硬性额度，也不代表无限免费。
- 失败或中断的上传可以在当前窗口重试，使用稳定对象 ID；不会因为重试重复收入。未完成预约会保守地计入配额。当前没有自动清理私人照片的任务；后续清理应先列出对象、确认预约过期且无引用，再执行。
- 不把私人照片、视频、导出备份上传到 GitHub；地图边界、网页代码和字体是静态公开资源。

## R2 接入

新函数的服务端环境支持：

- `JOURNEY_R2_ACCOUNT_ID`
- `JOURNEY_R2_BUCKET`
- `JOURNEY_R2_ACCESS_KEY_ID`
- `JOURNEY_R2_SECRET_ACCESS_KEY`

通过 Supabase 服务端配置或安全 CLI 输入设置，不要提交到仓库、网页配置或聊天记录。仅配置这些变量不负责创建存储桶、购买服务或迁移历史影像。

R2 桶保持私有，为网站的真实 origin 配置 CORS；开发 origin 单独列出：

```json
[{"AllowedOrigins":["https://yeewan-yi.github.io","http://127.0.0.1:4184"],"AllowedMethods":["GET","HEAD","PUT"],"AllowedHeaders":["Content-Type","Range"],"ExposeHeaders":["Content-Length","Content-Range","Accept-Ranges","ETag"],"MaxAgeSeconds":3600}]
```

临时读写链接限制到具体对象。R2 配置完成后，须实际验证上传、HEAD、分段读取、第二个人读取、跨房间拒绝及链接过期。当前没有实际 R2 账户联调证据。

## 地图搜索与容量

城市搜索由用户主动提交，不自动补全，不批量抓取。服务端为整个网站限制为至少 1.1 秒一次，双方共用限速和缓存；查询不附带房间信息给地图服务。缓存最多 100 份、30 天，仅清理公开地图搜索缓存，不影响私人回忆。Nominatim 来源可由 `JOURNEY_GEOCODER_URL` 切换；界面按要求显示 OpenStreetMap 署名。

城市地图同步先读轻量版本号，仅当点亮状态变化时取城市边界，避免每 12 秒重复下载全部多边形。评论窗口在可见且未翻历史时每 6 秒检查；仍采用轮询，未声称即时推送。

## 上线顺序

1. 恢复 Supabase 管理连接，检查现有 schema 与项目限制。
2. 执行 `supabase/journey.sql`（新增表、索引、受控入口和私有桶，不清空旧表）。
3. 部署 `supabase/functions/youqi-journey-media/index.ts` 为 `youqi-journey-media`，关闭平台 JWT 验证，保留函数内的房间及个人能力校验。
4. 执行真实事务回滚测试，并检查 Supabase advisors。重点核对私有表不可直接访问，以及两个身份和另一房间的隔离。
5. 使用一次性测试房间/合成文件验证照片、视频上传、真实大小校验、签名读取、双方评论、游标历史与失败重试。不要向实际房间发送测试评论。
6. 验证通过后再发布主站，避免新入口先上线而后台不可用。

`node --test` 为网页行为与地图测试；`node scripts/verify-journey-db.mjs` 在独立 PGlite PostgreSQL 内验证完整新增 SQL、角色隔离、配额和游标分页，不连接生产项目，不能代替真实 Storage / R2 联调。

正式资料需独立备份数据库索引与对象文件；数据库备份不包含影像本体。沿用 `docs/storage-plan.md` 与 `docs/photo-storage-plan.md` 的双副本和迁移核对原则。
